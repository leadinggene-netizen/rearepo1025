# Relay VPS deployment

Portal: https://relay.tradingviewtometatraders.com

The Ubuntu 24.04 VPS at `23.94.68.231` runs one Relay process and one connection for a demo trading account. MT5 stays on your Windows computer. The HTTPS deployment has fresh credentials and an empty journal; it does not inherit the local preview's keys, account binding or history.

## Open the portal

1. Open the portal URL above.
2. Connect to the VPS using your existing SSH key. In the Ubuntu root shell, run:

   ```sh
   python3 -c 'import json; print(json.load(open("/var/lib/relay/state.json"))["adminKey"])'
   ```

3. Paste that key into the portal. It remains in the browser tab's memory. Production startup does not print credentials into the service journal.

Treat the admin key as a password: it reveals the terminal and webhook keys and can authorize demo instructions. This is a single-operator demo, without multi-user login, MFA, automated key rotation or tenant isolation. Use its existing demo account restrictions.

## Move the demo EA to HTTPS

Before switching, check the old local portal and MT5 positions/history. Resolve any outstanding command or pending EA result against the old server first. The pending-result journal must not be deleted simply to make the new adapter connect.

1. Remove the old Relay EA from its chart. Keep only one Relay adapter attached across both endpoints.
2. Copy `mt5/RelayDemoRemote.mq5` (or the compiled `RelayDemoRemote.ex5`) to your terminal's `MQL5/Experts/Advisors` folder. Compile the source in MetaEditor with F7, then refresh Navigator.
3. In MT5, Tools -> Options -> Expert Advisors, add `https://relay.tradingviewtometatraders.com` to the allowed WebRequest URLs.
4. Attach RelayDemoRemote to one chart on the intended demo account. Set `BridgeUrl` to the HTTPS URL without a trailing slash, `TerminalKey` to the NEW key in the VPS portal, and `ExpectedLogin` to the demo account login. Retain your deliberate magic number and lot cap.
5. Enable Algo Trading and check that the VPS portal shows the correct account and broker as Connected. The first authorized heartbeat binds this server's connection to that account/broker.
6. Only after reviewing settings, send a small demo instruction and confirm its actual result in MT5. Deployment smoke tests do not submit orders or claim a remote broker execution test.

The original local EA is unchanged. The new adapter allows exactly the deployed HTTPS origin and the original localhost endpoint. Demo-account checks, lot limits, ownership rules and the existing result journal remain in force. Network timeout is five seconds for the remote endpoint.

## TradingView endpoint

Send JSON to `https://relay.tradingviewtometatraders.com/api/webhook/demo-mt5`, with the VPS webhook key in the `secret` field when custom headers are unavailable. Use the existing request contract and stable event IDs in README.md. Do not reuse the local preview's keys. The server rejects commands while the adapter is offline.

## Server layout

| Path | Contents |
|---|---|
| `/opt/relay/releases/<release-id>/` | Root-owned published application, static portal files, deployment configuration and release metadata |
| `/opt/relay/current` | Symlink to the active release |
| `/var/lib/relay/state.json` | Credentials, account binding and durable journal; mode 0600, owned by relay |
| `/var/lib/relay/` | Persistent state directory, mode 0700; retained between releases |
| `/etc/systemd/system/relay.service` | Dedicated unprivileged service with restricted filesystem access and memory limit |
| `/etc/nginx/conf.d/relay.conf` | HTTPS, SignalR upgrade, hostname/origin controls, 8 KiB request limit and per-IP request/connection limits |
| `/etc/letsencrypt/live/relay.tradingviewtometatraders.com/` | TLS certificate and private key; managed by Certbot |
| `/etc/letsencrypt/renewal-hooks/deploy/relay-nginx-reload` | Tests and reloads Nginx after certificate renewal |
| `/var/log/nginx/relay-access.log` | Method, path without query string, status and duration; no headers, bodies or query tokens |
| `/opt/relay/config-backups/` | Previous Nginx configuration retained by each release installation |

Nginx listens on 80/443. Only ACME challenges are served over HTTP; other valid-host HTTP requests redirect to HTTPS. The ASP.NET backend listens only on `127.0.0.1:5080` and retains its loopback peer check. Forwarded client IP/protocol headers are not trusted by the application; proxy limits use the actual external peer address. No HTTPS redirects are generated by the backend.

Existing SSH and NoMachine services remain active. The former x-ui/Xray service was stopped and disabled at startup at the user's request. No host firewall reset, root-login change, VPS reboot or account migration is part of this deployment.

## Build, update and check

Run from the project directory in PowerShell 7 with the .NET 10 SDK and Node 22:

```powershell
./scripts/test.ps1
./scripts/package-release.ps1 -ReleaseId 'YOUR-UNIQUE-RELEASE-ID'
```

The package script publishes framework-dependent .NET application files, checks for excluded local data, adds the deployment files, and produces a `.tar.gz` and SHA-256 file under `artifacts/releases/<release-id>/`. The included `release.json` records its source revision and whether the checkout contained uncommitted changes. Binaries, credentials, backup images and private keys are not committed.

Transfer the archive and `deploy/install-release.sh` by SCP using the already verified SSH host key. Then, in the VPS root shell:

```sh
bash /root/install-release.sh /root/relay-YOUR-UNIQUE-RELEASE-ID.tar.gz YOUR-UNIQUE-RELEASE-ID EXPECTED_SHA256
systemctl status relay nginx --no-pager
curl --fail https://relay.tradingviewtometatraders.com/health
```

The one-time prerequisites are Ubuntu's `aspnetcore-runtime-10.0`, `nginx` and `certbot` packages plus the issued webroot certificate. They are already installed on this VPS. Automatic certificate renewal uses `certbot.timer`. The installer verifies the archive checksum, creates an immutable release directory, switches the active symlink, restarts Relay, checks health, validates the proxy configuration and reloads Nginx. It does not delete persistent state.

GitHub CI builds and tests the source and packages the remote EA source with its artifacts. Deployment remains an explicit SSH operation, so a repository push cannot change the broker-connected service. Keep the SSH private key outside Git. A later GitHub environment can use manual approval and an SSH deployment secret after that access is deliberately configured.

For diagnostics, use `journalctl -u relay -n 50 --no-pager`, `nginx -t`, and `systemctl list-timers certbot.timer`. Avoid sharing credential files or log excerpts containing secrets. Keep Ubuntu runtime packages patched through normal server maintenance.

## Rollback and backup

For application-only rollback, stop Relay, change `/opt/relay/current` to a previously recorded release, and start Relay. Restore the corresponding service/proxy configuration if it changed. Preserve `/var/lib/relay`; a code rollback does not roll back account history. A restart makes any interrupted dispatched command unknown, requiring reconciliation in MT5.

The pre-deployment full-disk image remains only on the Windows computer, encrypted and UNVERIFIED. Verification was deferred at the user's request. It is not a confirmed restore point, and it predates Relay's server state. No disk-image restoration or upload was performed as part of deployment. Back up new Relay state separately with access restricted to the operator, when the service is stopped, before future state-changing migrations.
